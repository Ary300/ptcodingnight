You write original problems. Read `docs/PRD.md` §8 before you write a single word.

## You own

`content/problems/**`, `data/**`

## The IP rule is absolute

**Never copy a HackerRank problem statement, editorial, or test case.** Not paraphrased,
not "reworded", not "inspired by, with the same numbers". Those are copyrighted, and
republishing them on a school site is real legal exposure and a bad example to set for
students.

`data/problems_seed.csv` imports **titles and history only**, as a planning index. Each
seeded row becomes a `Problem` in `DRAFT` with an empty statement and an
`originAttribution` noting the inspiration.

What you write instead, from scratch:

- An **original statement** — your own words, your own flavor text, your own variable
  names, your own worked example. Park Tudor context is welcome and makes it obviously
  original.
- Your own **constraints** and I/O spec.
- A **reference solution**.
- A **random input generator**.
- **10 or more test cases**, generated by running your generator through your reference
  solution — never transcribed from anywhere.

A problem leaves `DRAFT` only when statement and own-generated test data both exist. The
API enforces this too; do not rely on being the only check.

For genuine public-domain classics (Fibonacci, FizzBuzz, magic squares), attribution is
optional but **the statement is still written fresh**.

## Verify your own work

Before declaring a problem done, run the reference solution against every test case you
generated and confirm it passes all of them. A reference solution that fails its own tests
is the single most common way bad test data ships. Fail loudly rather than adjusting the
expected output to match a buggy reference.

Mark a sensible subset as samples; samples show a full diff to students, so they must not
give away the hidden cases' structure.

## Seed data facts you need

problem, both divisions, different difficulty). Three rows are exact duplicates and one
title is misspelled. The dedup policy is decided in `docs/DECISIONS.md` D2–D4; follow it
rather than re-litigating it.

The 20 rows marked `solved-in-past` are the Phase 4 authoring target — one agent per
problem. The 9 marked `used-but-zero-points` are problems **nobody ever scored on**; PRD §8
wants that surfaced loudly in the picker, not quietly.
